## 2. 阶段定位与目标

### 2.1 目标与完成标志

阶段 3 要回答的问题是：**GPU 从"能上电"升级为"能干活"**。一句话目标：UMA/GART/GPUVM 可用；doorbell/IH/CP/MES 打通；用户态提交 PM4 拿到 fence。

**完成标志（系统走到哪一步）**：compute 测试的 magic 值正确——这意味着"CPU 写一段内存 → GPU 执行一段程序 → 结果回到 CPU"的完整闭环打通。此时用户态（RADV）已具备提交真实渲染工作的全部底层条件；屏幕仍由固件 GOP 扫描（显示接管属阶段 4）。这是"GPU 能算"的里程碑，也是 Cobalt64 阶段 17（ComputeDispatch）的等价物 [1]。

### 2.2 入口条件

1. **开工前先产出《阶段3-需求文档》**（见 2.3，这是第一条入口条件，不是可选项）。

3. 阶段 0/1 的 UMA carveout、FB location、GTT 取证值在手：本机实测 UMA carveout 4096 MiB（见《00-总体路线.md》附录 A）。

## 3. 主体章节

### 3.1 GMC 11.0 与 UMA 呈现

参考 Linux `gmc_v11_0.c` [19]；Cobalt64 的 `gmc_v12_0.cpp` 作模板。

**关键差异（独显 → APU）**：独显的 VRAM 是独立显存 + BAR0 大窗口；APU 的 VRAM 是系统内存 carveout（CPU 可直接访问），无独立 VRAM BAR。

**做法**：从 discovery/ATOM 读 `vram_size`/`fb_location`/`gtt_size`；配置 FB location、系统孔径（system aperture）、UMA 边界；UMA carveout 呈现为"VRAM"，其余系统内存呈现为"GTT"。

**本机实测**：UMA carveout 4096 MiB（阶段 0/1 实测，见《00-总体路线.md》附录 A）。

**nullarc 对照值 [37]（同 IP 版本对照值，需本机复核）**：UMA carveout 6144 MiB（`RCC_CONFIG_MEMSIZE`）、BAR0 256 MiB（FB aperture，物理地址在 32GiB 以上，写它不碰系统内存）、BAR2 门铃 2 MiB、BAR5 MMIO。

**寄存器（见《00-总体路线.md》附录 B）**：GC 段用 `regGCMC_VM_*`（`gc_11_0_0_offset.h`，如 FB_LOCATION_BASE=0x1678）；MMHUB 段用 `regMMMC_VM_*`（`mmhub_3_0_1_offset.h`，如 FB_LOCATION_BASE=0x08ec、SYSTEM_APERTURE_LOW/HIGH=0x08f1/0x08f2，BASE_IDX=1）——不存在名为 `GMC_VM_*` 的宏。

**通过标准**：`n48r3test mem` 输出 vram/gtt/fb_location；CPU 写 UMA 后 GPU 能读（SDMA 拷贝验证）。

### 3.2 GART 与 GPUVM

参考 Linux `amdgpu_gart.c`/`amdgpu_vm.c` [16]。

**PTE 位定义按 GFX11 校验**：GFX12 用 `MTYPE_GFX12_SHIFT=54`、`IS_PTE=1<<63`；GFX11 的 MTYPE shift 等差异以 Linux `amdgpu_vm.h` 为准，**待取证**（列入《阶段3-需求文档》）。

**nullarc 实证陷阱 [37]（同 IP 版本对照，需本机复核）**：

- GPUVM context0：gfxhub 寄存器全套照 Linux trace；页表放**系统内存**（root = phys\|3）；写 PTE 要 clflush。
- VMID 8 应用上下文：4 级表（目录在系统内存，PDE=phys\|7 无 BFS/TF）；IB with VMID 8 可执行；写到达需要 ACQUIRE_MEM（GL2 writeback）。
- 早期 GART-VA 不可用：所有 ring/MQD/fence 地址用 MC aperture（nullarc 值 0x80_xxxxxxxx，需本机复核）。
- 测试期用 FAULT_DEFAULT=1，避免翻译错误挂死 CP。

**通过标准**：`n48r3test gart` 输出 PTE=VALID\|IS_PTE；GPU 经 GART 读到已知 buffer；VMID 8 的 IB 执行成功。

### 3.3 Doorbell 与中断控制器（IH）

参考 Linux `amdgpu_doorbell_mgr.c`（及 `amdgpu_doorbell.h`）/`ih_v6_0.c`。**本机 IH 版本为 6.0.1**（《00-总体路线.md》附录 B 勘误：nullarc 780M 实机 discovery 实证 OSSSYS=6.0.1，Linux 选 `ih_v6_0.c`；`ih_v7_0.c` 存在但不适用本机）。

Cobalt64 的 doorbell 用 NAVI10 assignment（GFX11 同用此表 [20][27]），SDMA 是 QWORD index。

**步骤**：映射 BAR2 → 分配 index → IH ring → VM fault 解码。

**通过标准**：doorbell 自环成功；IH 收到并解码；VM fault 日志可读（client/src_id/VA）。

### 3.4 CP/MES 队列

参考 Linux `gfx_v11_0.c`（CP 初始化内嵌）/`mes_v11_0.c` [20][22]。

**nullarc 实证陷阱 [37]（同 IP 版本对照值，需本机复核）**：

- `CP_ME_CNTL` 要写 0x01000000（CE_HALT 保持），否则 PFP 挂在 RCIU；
- wptr-shadow（WB+16）要在 doorbell 之前；
- map_legacy_kq 需要 KIQ（RLC_CP_SCHEDULERS=0x30e8 + HQD me3/pipe1）。

**通过标准**：GFX/compute 队列创建；NOP/拷贝 IB 完成；fence <1ms。

### 3.5 用户客户端 ABI（N48N RDNA3）

复用 N48N selector 布局，新增 RDNA3 capability 位；BO 分配区分 UMA/GTT；CS 提交带 PM4 IB；fence 用内存值；scanout 接口预留 DCN 3.1.4。

nullarc 实证参照 [37]：Mesa mock 的 selector 契约（0..8）+ 后续扩展（doDbgAdoptQueue=112 等）可作 ABI 设计参照。

**通过标准**：`n48r3test submit` 提交 IB 拿到 fence；Mesa probe 能开设备。

### 3.6 compute 闭环测试

`store_magic` 的 gfx11 版汇编成 `.bin`，compute 队列提交，校验 magic。

nullarc 实证对照 [37]：vkprobe 256/256（ACO 编译 fill.comp，INDIRECT_BUFFER(VMID 8) + RELEASE_MEM；陷阱：IB 高位地址符号扩展 0xffff8001、doorbell 前 sfence（BAR0 是 write-combining）、clflush 缓冲）。vkprobe 256/256 是本阶段 compute 链路的对照基准（亦是阶段 4/5 性能守门指标之一，见 5.2）。

**通过标准**：`n48r3test compute` 输出 `magic=0x...` 与预期一致。

### 3.7 中间自检

吸收 Cobalt64 stage 16/17 的思想 [1]：队列创建后先跑 **PM4 级自检**（scratch 寄存器写读 + fence 等待，对应 Cobalt64 的 PM4Test）；再跑 **compute 自检**（shader 写 VRAM 逐 lane 校验，对应 ComputeDispatch）；两者都过才进入用户态 ABI 联调。

VM 子系统自检清单采用 Cobalt64 S1b 的五腿自检：低地址/高地址/混合/compute/故意 fault [1]。

### 5.2 稳定性考核（soak）与证据要求

**soak 阶梯（项目统一说法）**：阶段 3 = **单次开机全通过**——上表全部子步在同一次开机内依次通过、无 SKIPPED，即达到阶段 3 完成标准。

**性能守门指标**：fence 完成延迟 <1ms（本阶段即须满足，并延续到阶段 4/5 复测）；vkprobe 256/256 作为 compute 链路对照基准。

**证据要求**：

- 每项通过标准的命令输出、寄存器值、日志行落盘归档；
- nullarc 对照证据键（E6–E9）引用其 `stage3-acceleration-plan.md` [37]，引用处标注"同 IP 版本对照值，需本机复核"；
- 失败处理流程（项目统一流程）：记录（日志/寄存器快照/IH/VM fault/boot-arg）→ latch off（本 boot 关闭该路径）→ 回退（关 boot-arg 回上一阶段）→ 回顾（失败模式入《00-总体路线.md》附录 C；设计问题回阶段 0 补取证）→ 不掩盖（不靠重试/忽略/放宽校验让失败消失）。

## 6. 风险与回退

| 风险 ID | 风险 | 概率/影响 | 缓解与回退 |
|---|---|---|---|
| R2 | APU 的 UMA 无法呈现为 Apple 可用的 VRAM/GART | 中→低 / 高 | BAR aperture 拓扑与 nullarc 同构（正面信号）+ TTL 对象创建成功无内存失败；本机 carveout 4096 MiB 已实测；GMM 回调适配；不成则暂停 |
| R5 | GPU hang 整机无响应 | 中 / 高 | 默认关闭 + 超时 + latch off + 人工恢复（长按电源键，记录 hang 前最后一条日志） |
| R11 | nullarc 与本机的平台差异 | 中 / 中 | nullarc 实测机为 Firebat U6C（0x1900）/ GC 11.0.1，本机为 ThinkBook 14+（0x15BF）/ GC 11.0.1：同 IP 版本、不同平台。流程与陷阱清单可参照，其平台相关数值（MC aperture、BAR0 等）不作本机真值，引用处标注"需本机复核"，以本机 IP discovery 与实测为准 |

**boot-arg 回退**：`n48r3-gart=0`、`n48r3-mes=0`、`n48r3-queue=0` 分别关闭对应子系统；失败时 `dump_failure_state`（VM fault/IH/队列状态）→ 返回阶段 2。测试期用 FAULT_DEFAULT=1（翻译错误不挂死 CP，nullarc 实证）。

| 术语 | 解释 |
|---|---|
| UMA carveout | APU 中从系统内存划给核显专用的一段内存，本机实测 4096 MiB；驱动把它呈现为"VRAM"。 |
| GTT | Graphics Translation Table 管理的系统内存段：carveout 之外的系统内存，GPU 经页表访问。 |
| GMC | GPU 内存控制器（Graphics Memory Controller），负责 FB location/系统孔径/页表硬件。 |
| PTE / PDE / root | 页表项/页目录项/页表根；`phys\|3`、`phys\|7` 为 nullarc 实测的根/目录编码（需本机复核）。 |
| VMID | GPU 虚拟机标识；VMID 8 是应用上下文（4 级页表）。 |
| MC aperture | GPU 视角的物理地址窗口（nullarc 值 0x80_xxxxxxxx，需本机复核）；早期 GART-VA 不可用时代替页表地址使用。 |
| clflush | x86 把缓存行写回内存的指令；写 PTE 后必须执行，否则 GPU 读到旧值。 |
| GL2 writeback / ACQUIRE_MEM | GPU 二级缓存的写回机制；VMID 8 下写到达内存需要 ACQUIRE_MEM 触发 GL2 writeback。 |
| FAULT_DEFAULT | 页翻译错误的默认处理策略；测试期置 1，翻译错误不挂死 CP。 |
| doorbell | GPU 的"敲门"寄存器（BAR2 映射）：写它通知硬件队列有新工作。 |
| IH | Interrupt Handler，中断控制器（本机 6.0.1）；收 doorbell/VM fault 等事件进 ring。 |
| PM4 / IB | AMD GPU 命令流格式 / Indirect Buffer（命令缓冲块）。 |
| CP / PFP / RCIU / CE_HALT | 命令处理器及其前端（PFP）/接口（RCIU）；`CP_ME_CNTL`=0x01000000 保持 CE 停机（nullarc 实证）。 |
| MES | Micro Engine Scheduler，队列调度固件（本机 11.0）。 |
| wptr-shadow（WB+16） | 写指针的影子副本（write-back 槽 +16 偏移）；必须在 doorbell 之前就绪。 |
| KIQ / HQD | Kernel Interface Queue（内核管理队列）/ Queue Descriptor 的 HQD 寄存器组；map_legacy_kq 需 KIQ（RLC_CP_SCHEDULERS=0x30e8 + HQD me3/pipe1）。 |
| MQD | Memory Queue Descriptor，队列的内存描述结构。 |
| fence | GPU 完成标记：写一个内存值，CPU 轮询它判断完成；要求延迟 <1ms。 |
| sfence | x86 写屏障指令；doorbell 前必须执行（BAR0 是 write-combining）。 |
| 符号扩展 0xffff8001 | IB 高位地址的编码约定（nullarc 实证陷阱）。 |
| store_magic | compute 测试着色器：GPU 执行后把约定魔数写入内存，CPU 校验。 |
| vkprobe | nullarc 的 Vulkan 探针套件，256/256 全通过为其对照基准。 |
| selector | N48N 用户客户端 ABI 的命令选择子（0..8 及扩展）。 |
| RADV | Mesa 的 AMD Vulkan 驱动（全局术语表已有，此处指其在本项目的 APU 适配角色）。 |
