## 2. 阶段定位与目标

### 2.1 目标与完成标志

阶段 3 要回答的问题是：**GPU 从"能上电"升级为"能干活"**。一句话目标：UMA/GART/GPUVM 可用；doorbell/IH/CP/MES 打通；用户态提交 PM4 拿到 fence。

**完成标志（系统走到哪一步）**：compute 测试的 magic 值正确——这意味着"CPU 写一段内存 → GPU 执行一段程序 → 结果回到 CPU"的完整闭环打通。此时用户态（RADV）已具备提交真实渲染工作的全部底层条件；屏幕仍由固件 GOP 扫描（显示接管属阶段 4）。这是"GPU 能算"的里程碑，也是 Cobalt64 阶段 17（ComputeDispatch）的等价物 [1]。

### 2.2 入口条件

1. **开工前先产出《阶段3-需求文档》**（见 2.3，这是第一条入口条件，不是可选项）。

3. 阶段 0/1 的 UMA carveout、FB location、GTT 取证值在手：本机实测 UMA carveout 4096 MiB（见《00-总体路线.md》附录 A）。

## 3. 主体章节

### 3.1 GMC 11.0 与 UMA 呈现

参考 Linux `gmc_v11_0.c` [19]；Cobalt64 的 `gmc_v12_0.cpp` 作模板。

**关键差异（独显 → APU）**：独显的 VRAM 是独立显存 + BAR0 大窗口；APU 的 VRAM 是系统内存 carveout（CPU 可直接访问），无独立 VRAM BAR。

**做法**：从 discovery/ATOM 读 `vram_size`/`fb_location`/`gtt_size`；配置 FB location、系统孔径（system aperture）、UMA 边界；UMA carveout 呈现为"VRAM"，其余系统内存呈现为"GTT"。

**本机实测**：UMA carveout 4096 MiB（阶段 0/1 实测，见《00-总体路线.md》附录 A）。

**nullarc 对照值 [37]（同 IP 版本对照值，需本机复核）**：UMA carveout 6144 MiB（`RCC_CONFIG_MEMSIZE`）、BAR0 256 MiB（FB aperture，物理地址在 32GiB 以上，写它不碰系统内存）、BAR2 门铃 2 MiB、BAR5 MMIO。

**寄存器（见《00-总体路线.md》附录 B）**：GC 段用 `regGCMC_VM_*`（`gc_11_0_0_offset.h`，如 FB_LOCATION_BASE=0x1678）；MMHUB 段用 `regMMMC_VM_*`（`mmhub_3_0_1_offset.h`，如 FB_LOCATION_BASE=0x08ec、SYSTEM_APERTURE_LOW/HIGH=0x08f1/0x08f2，BASE_IDX=1）——不存在名为 `GMC_VM_*` 的宏。

**通过标准**：`n48r3test mem` 输出 vram/gtt/fb_location；CPU 写 UMA 后 GPU 能读（SDMA 拷贝验证）。

### 3.2 GART 与 GPUVM

参考 Linux `amdgpu_gart.c`/`amdgpu_vm.c` [16]。

**PTE 位定义按 GFX11 校验**：GFX12 用 `MTYPE_GFX12_SHIFT=54`、`IS_PTE=1<<63`；GFX11 的 MTYPE shift 等差异**已取证**（gfx9 走 bit57、gfx10 走 bit48 `AMDGPU_PTE_MTYPE_NV10_SHIFT`；完整位表见《阶段3-需求文档》§4.1，amdgpu_vm.h:57-136）。

**GART 使能必须两个 hub 对称执行**（真机 boot4 实证，已落地）：GART 访问由 GC（GFXHUB）与 MMHUB 两条 VM 通路承载（图形/计算队列走 GFXHUB，SDMA 等走 MMHUB）。Linux 的 `gfxhub_v3_0_gart_enable`/`mmhub_v3_0_1_gart_enable` 是同构序列（mmhub_v3_0_1.c:150-367：AGP aperture、系统 aperture、L1/L2 缓存配置、fault 控制、identity aperture 关闭、VMID 编程、TLB 失效）。只初始化 GC 侧时，SDMA 经 MMHUB 的 GART 访问不会被正确路由，且表现为**静默超时、无 fault**（boot4 即此形态：写满预算、双 hub fault=0）。因此本驱动在 `seq_hub_pre` 中为 MMHUB 补齐与 GC 对称的 17 个寄存器写入（偏移以 `mmhub_3_0_1_offset.h` 为准）以及第 6 步 identity aperture 关闭（0x0712-0x0717 写 0xFFFFFFFF/0x0000000F/0/0/0/0，见 mmhub_v3_0_1.c:284-303），写行注册 `kMesRows` 并在 `mes-hub` 证据中回读。

**nullarc 实证陷阱 [37]（同 IP 版本对照，需本机复核）**：

- GPUVM context0：gfxhub 寄存器全套照 Linux trace；页表放**系统内存**（root = phys\|3）；写 PTE 要 clflush。
- VMID 8 应用上下文：4 级表（目录在系统内存，PDE=phys\|7 无 BFS/TF）；IB with VMID 8 可执行；写到达需要 ACQUIRE_MEM（GL2 writeback）。
- 早期 GART-VA 不可用：所有 ring/MQD/fence 地址用 MC aperture（nullarc 值 0x80_xxxxxxxx，需本机复核）。
- 测试期用 FAULT_DEFAULT=1，避免翻译错误挂死 CP。

**通过标准**：`n48r3test gart` 输出 PTE=VALID\|IS_PTE；GPU 经 GART 读到已知 buffer；VMID 8 的 IB 执行成功。

### 3.3 Doorbell 与中断控制器（IH）

参考 Linux `amdgpu_doorbell_mgr.c`（及 `amdgpu_doorbell.h`）/`ih_v6_0.c`。**本机 IH 版本为 6.0.1**（《00-总体路线.md》附录 B 勘误：nullarc 780M 实机 discovery 实证 OSSSYS=6.0.1，Linux 选 `ih_v6_0.c`；`ih_v7_0.c` 存在但不适用本机）。

Cobalt64 的 doorbell 用 NAVI10 assignment（GFX11 同用此表 [20][27]），SDMA 是 QWORD index。

**步骤**：映射 BAR2 → 分配 index → IH ring → VM fault 解码。

**通过标准**：doorbell 自环成功；IH 收到并解码；VM fault 日志可读（client/src_id/VA）。

### 3.4 CP/MES 队列

参考 Linux `gfx_v11_0.c`（CP 初始化内嵌）/`mes_v11_0.c` [20][22]。

**nullarc 实证陷阱 [37]（同 IP 版本对照值，需本机复核）**：

- `CP_ME_CNTL` 要写 0x01000000（CE_HALT 保持），否则 PFP 挂在 RCIU；
- wptr-shadow（WB+16）要在 doorbell 之前；
- map_legacy_kq 需要 KIQ（RLC_CP_SCHEDULERS=0x30e8 + HQD me3/pipe1）。

**通过标准**：GFX/compute 队列创建；NOP/拷贝 IB 完成；fence <1ms。

### 3.5 用户客户端 ABI（N48N RDNA3）

复用 N48N selector 布局，新增 RDNA3 capability 位；BO 分配区分 UMA/GTT；CS 提交带 PM4 IB；fence 用内存值；scanout 接口预留 DCN 3.1.4。

nullarc 实证参照 [37]：Mesa mock 的 selector 契约（0..8）+ 后续扩展（doDbgAdoptQueue=112 等）可作 ABI 设计参照。

**通过标准**：`n48r3test submit` 提交 IB 拿到 fence；Mesa probe 能开设备。

### 3.6 compute 闭环测试

`store_magic` 的 gfx11 版汇编成 `.bin`，compute 队列提交，校验 magic。

nullarc 实证对照 [37]：vkprobe 256/256（ACO 编译 fill.comp，INDIRECT_BUFFER(VMID 8) + RELEASE_MEM；陷阱：IB 高位地址符号扩展 0xffff8001、doorbell 前 sfence（BAR0 是 write-combining）、clflush 缓冲）。vkprobe 256/256 是本阶段 compute 链路的对照基准（亦是阶段 4/5 性能守门指标之一，见 5.2）。

**通过标准**：`n48r3test compute` 输出 `magic=0x...` 与预期一致。

### 3.7 中间自检

吸收 Cobalt64 stage 16/17 的思想 [1]：队列创建后先跑 **PM4 级自检**（scratch 寄存器写读 + fence 等待，对应 Cobalt64 的 PM4Test）；再跑 **compute 自检**（shader 写 VRAM 逐 lane 校验，对应 ComputeDispatch）；两者都过才进入用户态 ABI 联调。

VM 子系统自检清单采用 Cobalt64 S1b 的五腿自检：低地址/高地址/混合/compute/故意 fault [1]。

### 5.2 稳定性考核（soak）与证据要求

**soak 阶梯（项目统一说法）**：阶段 3 = **单次开机全通过**——上表全部子步在同一次开机内依次通过、无 SKIPPED，即达到阶段 3 完成标准。

**性能守门指标**：fence 完成延迟 <1ms（本阶段即须满足，并延续到阶段 4/5 复测）；vkprobe 256/256 作为 compute 链路对照基准。

**证据要求**：

- 每项通过标准的命令输出、寄存器值、日志行落盘归档；
- nullarc 对照证据键（E6–E9）引用其 `stage3-acceleration-plan.md` [37]，引用处标注"同 IP 版本对照值，需本机复核"；
- 失败处理流程（项目统一流程）：记录（日志/寄存器快照/IH/VM fault/boot-arg）→ latch off（本 boot 关闭该路径）→ 回退（关 boot-arg 回上一阶段）→ 回顾（失败模式入《00-总体路线.md》附录 C；设计问题回阶段 0 补取证）→ 不掩盖（不靠重试/忽略/放宽校验让失败消失）。

## 6. 风险与回退

| 风险 ID | 风险 | 概率/影响 | 缓解与回退 |

## 9. T-E：驱动卸载/拆除规程（normative）

**编写意图**：本章规定驱动从“用户态停止提交、内核开始卸载”到“所有 GPU 队列静止、引擎停机”的最小安全序列，作为阶段 3 拆除实现（审计总账 B#16、A#10/#11/#12/#20/#21、B#18）的唯一规范依据。本章由 W0 交付，以《实施方案A》§1 的 T-E 草案为基，按《实施方案定稿裁决书》§二.11 修订：拆除总序固定为 MES→SDMA→GFX→IH，SDMA 内部固定为 RB→IB→F32，**不设 SMU 拆除阶段**。

**读者**：W1b 拆除实现者、代码评审者、真机验收者。

**适用范围**：驱动 `stop()`/卸载路径、初始化失败后的回退路径（B#16），以及任何需要把队列与引擎恢复到静止态的诊断路径。不适用于日常渲染热路径，也不适用于电源管理挂起路径（见 io-contract IO-5、INV-D6）。

**落点与编号**：为保持既有章节编号稳定，本章顺延为第 9 章，既有第 8 章“本章术语”不重编号。

**出处复核**：本章引用的 Linux 行号、寄存器偏移与位号，已逐条对 `evidence/src/linux-7.2.0/` 快照复核：偏移取自 `drivers/gpu/drm/amd/include/asic_reg/gc/gc_11_0_0_offset.h` 与 `.../oss/osssys_6_0_0_offset.h`，位号取自对应 `*_sh_mask.h`。行号仅作定位辅助，代码注释应以“文件:函数”为主；上游版本升级后行号可能漂移。

### T-E.0 目的与设计意图

T-E 的目标不是“把寄存器清零”，而是让 GPU 在驱动卸载后处于可被下一次上电重新初始化的确定状态，同时不因拆除本身引入新的挂死。设计意图分三层：

1. **协议层先于电气层**：AMD 固件要求 HQD 先通过 DEQUEUE 请求退出调度，再改 ACTIVE/WPTR/RPTR。直接清 ACTIVE 会让 MES 仍持有该 HQD 的调度状态，下一次 SET_HW/ADD_QUEUE 可能观察到幽灵队列。依据：Linux `mes_v11_0.c: mes_v11_0_kiq_dequeue()`（1521-1554）的 kiq_dequeue 即此意图。
2. **先队列、后引擎、最后中断路由**：HQD 静止后才 halt ME/PFP/MEC/SDMA；IH 最后关闭，避免停机过程中丢失本可用于诊断的中断。依据：`gfx_v11_0.c: gfx_v11_0_cp_gfx_enable()`（3166-3185）、`sdma_v6_0.c: sdma_v6_0_gfx_stop()`（395-408）与 `sdma_v6_0_enable()`（453-471）。
3. **可回退、不 panic**：每一步必须有界轮询、失败记录、继续执行后续步骤。拆除是尽力而为（best-effort），任何单步失败不得阻断其余步骤，也不得触发内核 panic（INV-B3、INV-B4、PC-12）。

**不设 SMU 拆除**：SMU 的电源、时钟、电压寄存器属 io-contract IO-5 的禁止域；卸载阶段不写 SMU，也不以“拆除”为名新增 SMU 流程。PSP 同理，见 T-E.2 的 T-E-5。

### T-E.2 拆除总顺序（normative）

```
T-E-1  MES：逐队列 DEQUEUE → 关门铃 → 复位 MES 管道 / halt
T-E-2  SDMA：RB_ENABLE=0 → IB_ENABLE=0 → F32 halt
T-E-3  GFX：ME/PFP halt（同一次 RMW）→ MEC ME1/ME2 halt
T-E-4  IH：RB_ENABLE=0（ring0 另清 ENABLE_INTR），RPTR/WPTR=0
T-E-5  PSP：不执行任何写；仅当失败确实发生在 PSP 阶段（failed_ip_valid && failed_ip==Psp）时整段返回；其它阶段失败必须执行 T-E-1..T-E-4（B#16）
```

**顺序不可交换**。理由：MES 是队列的所有者，必须先静止；SDMA/GFX 是执行引擎，随后停机；IH 是中断路由，最后关闭。SDMA 内部顺序固定为 RB→IB→F32，依据 Linux `sdma_v6_0.c: sdma_v6_0_gfx_stop()`（395-408，先 RB 后 IB）与 `sdma_v6_0_enable()`（453-471，随后 F32 halt）；本顺序不采用方案B 的 SDMA 变体（裁决书§二.11）。

**不设 SMU 阶段**：任何“先关 SMU 时钟/电源再拆队列”的设想都违背 IO-5 与 AMD 的电源管理设计意图，本章不采纳。

### T-E.3 MES 队列拆除（每队列）

对 compute pipe0、gfx pipe1 各执行一次；顺序不可交换：

1. **选择队列**：写 `GRBM_GFX_CNTL`（0x0900，BASE_IDX 1）= `(3u << GRBM_GFX_CNTL__MEID__SHIFT) | pipe`，即 `0x0Cu | pipe`（MEID=3 表示 MES，PIPEID=pipe）。依据：Linux `soc21.c: soc21_grbm_select()`（REG_SET_FIELD 写 MEID/PIPEID）；`gc_11_0_0_sh_mask.h:24045-24048` 定义 PIPEID shift=0x0、MEID shift=0x2。**注意**：不得使用 `(3u << 16) | pipe`——该写法落在保留位，MEID 实际为 0，会选中 GFX ME0 而非 MES ME3。
2. **DEQUEUE 先行**：读 ACTIVE；若 `ACTIVE & 1`：
   - 写 `CP_HQD_DEQUEUE_REQUEST = 1`；
   - 以 `T_E_POLL_US` 轮询 ACTIVE 直到 bit0=0 或 `T_E_POLL_MAX` 超时；
   - 超时：记录 `N48R3LOG teardown: dequeue timeout pipe=%u active=0x%08x`，继续第 3 步。
3. **关门铃**：读 `CP_HQD_PQ_DOORBELL_CONTROL`，RMW 清 bit30（ENABLE）、置 bit31（HIT），写回；再写 0（Linux `mes_v11_0.c: mes_v11_0_kiq_dequeue()` 的清零形态，1541-1545）。
4. **清指针**：`WPTR_LO=0`、`WPTR_HI=0`、`RPTR=0`。此三步仅在 DEQUEUE 完成或超时后执行。
5. **取消选择**：写 `GRBM_GFX_CNTL = 0`。

**禁止**：在第 2 步之前写 ACTIVE=0；禁止用读回 ACTIVE 代替 DEQUEUE；禁止先清 WPTR/RPTR 再 DEQUEUE。

**依据**：Linux `mes_v11_0.c: mes_v11_0_kiq_dequeue()`（1521-1554，含 `soc21_grbm_select(adev, 3, ring->pipe, 0, 0)` 的 me=3）；`gfx_v11_0.c: gfx_v11_0_kiq_init_register()`（4457 起，含同型“若 ACTIVE 则 DEQUEUE”的初始化侧写法，4486-4499）。寄存器偏移见 `gc_11_0_0_offset.h:4604-4714`。

### T-E.4 MES 引擎停机

所有队列 DEQUEUE 完成后（无论单队列是否超时）：

1. 读 `CP_MES_CNTL`（0x2807），一次 RMW 写回：清 `MES_PIPE0_ACTIVE`（bit26）与 `MES_PIPE1_ACTIVE`（bit27），置 `MES_INVALIDATE_ICACHE`（bit4）、`MES_PIPE0_RESET`（bit16）、`MES_HALT`（bit30）=1；`MES_PIPE1_RESET`（bit17）与初始化时的 `enable_mes_kiq` 取值一致（启用 MES KIQ 时为 1）。
2. 读回 `CP_MES_CNTL` 并记录；不要求 ACTIVE 位立即为 0（硬件在 reset 后异步清），但要求写入已生效（读回值与写入值在可写位上一致）。

**依据**：Linux `mes_v11_0.c: mes_v11_0_enable(..., false)`（957-1017）：PIPE0/1 ACTIVE=0、ICACHE 失效、PIPE0_RESET=1、PIPE1_RESET 按 `enable_mes_kiq`、HALT=1，**一次 RMW 写回**，不插入额外延时；位号见 `gc_11_0_0_sh_mask.h:27811-27820`。本规程与上游同形态，不拆成多次写。

### T-E.5 SDMA 停机

对 `adev->sdma.num_instances` 个实例逐一执行（实例偏移用 `sdma_v6_0_get_reg_offset(adev, i, reg)` 换算），顺序不可交换：

1. 读 `SDMA0_QUEUE0_RB_CNTL`（实例 0 偏移 0x0080），清 `RB_ENABLE`（bit0），写回。
2. 读 `SDMA0_QUEUE0_IB_CNTL`（实例 0 偏移 0x008A），清 `IB_ENABLE`（bit0），写回。
3. 读 `SDMA0_F32_CNTL`（实例 0 偏移 0x589A，BASE_IDX 1），置 `HALT`（bit0）=1，写回。

**依据**：Linux `sdma_v6_0.c: sdma_v6_0_gfx_stop()`（395-408：对 `adev->sdma.num_instances` 循环，先 RB_ENABLE=0 再 IB_ENABLE=0）与 `sdma_v6_0_enable(..., false)`（453-471：调用 gfx_stop/rlc_stop 后对每个实例写 F32 HALT=1）。偏移与位号见 `gc_11_0_0_offset.h:190/208/1744`、`gc_11_0_0_sh_mask.h:5103`。

### T-E.6 GFX 引擎停机

1. 读 `CP_ME_CNTL`（0x0803），置 `ME_HALT`（bit28）=1、`PFP_HALT`（bit26）=1，写回；保留 `CE_HALT`（bit24）等既有位（RMW，不清零）。
2. 以 `T_E_POLL_US` 轮询 `CP_STAT`（0x0F40）直到读数为 0 或 `T_E_POLL_MAX` 超时；超时记录 `N48R3LOG teardown: gfx halt timeout cp_stat=0x%08x`，继续第 3 步。
3. 读 `CP_MEC_CNTL`（0x0802），置 `MEC_ME1_HALT`（bit30）=1、`MEC_ME2_HALT`（bit28）=1，写回；随后 `udelay(T_E_MEC_HALT_US)`。

**依据**：Linux `gfx_v11_0.c: gfx_v11_0_cp_gfx_enable(..., false)`（3166-3185：ME_HALT/PFP_HALT 后轮询 CP_STAT==0，超时打印 “failed to halt cp gfx”）与 `gfx_v11_0_cp_compute_enable(..., false)`（3894-3908：MEC_ME1/ME2_HALT 后 `udelay(50)`）。位号见 `gc_11_0_0_sh_mask.h:23985-24020`。

### T-E.7 IH 停机

1. 读 `IH_RB_CNTL`（OSSSYS 0x0080），RMW 清 `RB_ENABLE`（bit0）；若为 ring0，再清 `ENABLE_INTR`（bit17），写回。
2. 写 `IH_RB_RPTR`（0x0083）=0、`IH_RB_WPTR`（0x0084）=0。

**依据**：本机 IH 版本 6.0.1 走 `ih_v6_0.c: ih_v6_0_toggle_ring_interrupts(..., false)`（127-188：RB_ENABLE=0；ring0 另清 ENABLE_INTR；写回后 rptr/wptr=0）。`vega10_ih.c` 为同族旧 IP 实现，不作为本机依据。偏移与位号见 `osssys_6_0_0_offset.h:112-120`、`osssys_6_0_0_sh_mask.h:170-178`。

### T-E.8 失败处理与可观测性

1. **不提前返回**：T-E-1..T-E-4 中任一单步失败（读不可达、写被拒、超时、读回不符）只记录并继续后续步骤；最终汇总 `N48R3LOG teardown: done fails=%u`。
2. **失败分类**：每步至少区分 `denied`（分类器拒绝）、`timeout`（有界轮询超时）、`readback`（读回与写入不符）、`unreadable`（读失败），并计入失败计数；不得静默 `return` 或 `continue`（INV-D12）。
3. **幂等**：重复调用拆除路径时，已静止的队列（ACTIVE bit0=0）只记录 `already inactive`，不重复写 DEQUEUE/指针；不释放、不清零 golden 表与 grant 表。
4. **不 panic、不重试、不自动重启**：拆除失败置 latch 并暴露证据，不进入重试循环（PC-12、INV-B4）。
5. **证据归属**：拆除日志与进度令牌必须落持久通道；日志通道不可达时不得把日志当作验收判据（INV-E4）。

### T-E.9 与初始化（S0–S13）的对称性

| 初始化动作 | 对应拆除动作 | 说明 |
|---|---|---|
| MES ADD_QUEUE / SET_HW（S10–S12） | T-E.3 每队列 DEQUEUE + 关门铃 + 清指针 | 队列的所有者先静止 |
| MES 使能（CP_MES_CNTL ACTIVE/RESET） | T-E.4 MES 停机 | 复位与 halt 为逆操作 |
| SDMA RB/IB 使能、F32 解 halt | T-E.5 RB→IB→F32 | 与初始化同向，逐项取反 |
| GFX ME/PFP/MEC 使能 | T-E.6 halt | 保留 CE_HALT 等既有位 |
| IH RB 使能、指针设置 | T-E.7 RB_ENABLE=0（ring0 清 ENABLE_INTR）、指针清零 | 最后关闭中断路由 |

**对称性规则**：任何新增的初始化寄存器写，必须同时给出对应的拆除动作，或在代码注释与本表书面豁免并说明“无需逆操作”的理由（INV-A8）。只读寄存器不要求逆操作。

**无需逆操作的 b 类偏离（GART START/END）**：GART START/END 属初始化配置，T-E 不设逆操作。`gmc_v11_0.cpp` 写全空间（START=0、END=0xf_ffffffff），是 b 类有理由偏离：nullarc `PhxBringup.cpp:618-621` 同机实测与项目逐字一致（主 agent 亲验），而 Linux `gmc_v11_0.c` 的 GART START/END 按 PCI 独显场景放在 HIGH 区间，其对象（独立显存 + BAR 窗口）不适用于本机 APU/UMA。决策记录见 `.trellis/research/13-stage3-fix-decisions.md` §1 与 `tmp/main/audit-ledger-final.md` §三；真实驱动接管（阶段4+）若需收缩 GART 窗口，须先改此处并同步本册。

### T-E.10 禁止清单（normative）

1. 禁止在 DEQUEUE 之前清 `CP_HQD_ACTIVE`，或用读回 ACTIVE 代替 DEQUEUE。
2. 禁止先写 ACTIVE/WPTR/RPTR 再 DEQUEUE。
3. 禁止在拆除期写 SMU 电源、时钟、电压寄存器（IO-5 禁止域）。
4. 禁止在 PSP 阶段执行拆除写；PSP 失败只作短路返回（T-E-5）。
5. 禁止用 `r3_io_write32` 直写绕过分类器与读回；拆除写必须经 `td_write()`。
6. 禁止在拆除中释放、清零或重建 golden 表、grant 表、写命中位图。
7. 禁止失败后 panic、自动重试或自动重启（PC-12）。
8. 禁止为拆除专用行放宽 `td_ensure_reg` 的“注册且真写过”语义；此类行只能走 `td_ensure_teardown_reg`（T-E.11）。
9. 禁止对未在 grant 表注册的地址写；`td_ensure_teardown_reg` 必须为真才允许写。
10. 禁止无界忙等；所有轮询受 `T_E_POLL_MAX` 约束。
11. 禁止引入 SMU 拆除阶段或“先关 SMU 再拆队列”的顺序。
12. 禁止使用 `(3u << 16) | pipe` 选择 MES 队列（见 T-E.3 第 1 步）。

### T-E.11 验证要求（normative）

**逆操作行的判定语义**：

- `td_ensure_teardown_reg(addr, cls, owner, tag)` 的语义是**只验证“已注册”**：grant 表中存在匹配该单地址行（`start==addr`、非 range、`dwords==1`、owner/cls 一致）的条目即返回真；**不要求**该地址在初始化期被写过。字段匹配以实现登记结构为准。
- `td_ensure_reg(addr, cls, owner, tag)` 保持“注册且真写过”（`r3_wg_was_written(addr)`）语义，不得放宽（B#20）。
- 两者必须严格区分：DEQUEUE、DOORBELL_CONTROL、WPTR_LO/HI、RPTR、CP_ME_CNTL、CP_MEC_CNTL 等拆除逆操作行使用 `td_ensure_teardown_reg`；普通可逆对象继续使用 `td_ensure_reg`。若误用 `td_ensure_reg`，成功路径未写过的行会被判“无逆对象”而跳过，导致 T-E 跳过自己的逆操作。

**两类拆除行（E1 裁决）**：按初始化期是否真实写过，拆除写对象分两类，登记与门禁必须对应：

| 类别 | 判定 | 典型行 | 登记与门禁 |
|---|---|---|---|
| 拆除专用行 | 初始化期不写，只在 T-E 窗口写逆操作 | MES 拆除的 DEQUEUE/WPTR_LO/HI（0x1FC1/0x1FDF/0x1FE0）、GFX halt 的 CP_ME_CNTL/CP_MEC_CNTL | grant 表显式登记（tag 如 `reg:gfx-teardown`、`reg:teardown:mes`），写前用 `td_ensure_teardown_reg()` 只验注册 |
| 引导期对象逆转行 | 初始化期真实写过，拆除时逆转关闭 | IH_RB_CNTL（引导期置 RB_ENABLE；拆除时清 RB_ENABLE，ring0 再清 ENABLE_INTR） | 走常规 `td_ensure_reg()`：注册且 `r3_wg_was_written(addr)` 为真才允许写 |

区分标准只有一条：以写命中位图 `r3_wg_was_written` 的客观记录为准，不以“表里登记过”代替（INV-D13）。引导期写过的对象不得借 `td_ensure_teardown_reg` 绕过“真写过”检查；反之，拆除专用行若误走 `td_ensure_reg`，会因恒假而永不执行（W1b 第 8 节 E1）。

**注册预算**：

- MES 拆除行 3 条加在 `kMesQueueRows` 末尾：0x1FC1（DEQUEUE）、0x1FDF（WPTR_LO）、0x1FE0（WPTR_HI）；表计数 74→77。0x1FB8（DOORBELL_CONTROL）与 0x1FB3（RPTR）已在既有 MES 行声明，不得重复添加。
- GFX halt 行 2 条（CP_ME_CNTL 0x0803、CP_MEC_CNTL 0x0802）由 GFX entry 以拆除专用（teardown-only，tag `reg:gfx-teardown`）注册。
- `GRANT_MAX=200`、`EXPECT_MAX=80`：本波 `GRANT_MAX` 由 192 提升到 200（W2 IH 输入行 6 条 grant 注册所致），`EXPECT_MAX` 仍为 80 不扩；各包只加自己的行并以 `static_assert` 锁定当波值；跨包冲突上报主 agent（裁决书§二.8）。
- GDS-62 接线前置：G13/G14/G17 阶段3 函数（`gfx_v11_0_stage3_substep`）当前为显式延迟项，不接运行路径。接线前须先把 `GRANT_MAX` 提升到 ≥252：该路径按 stride 动态登记 62 条（60 个 GDS per-VMID 实例 + SPI_GDBG_PER_VMID_CNTL + RLC_SRM_CNTL）；现预算的 6 条计划行（G13 5 + G17 1）届时由这 62 条替换，全链预算 196−6+62=252。接线时同步补 `static_assert` 并复跑 `test_write_budget`。

**测试要求（host）**：

1. `td_ensure_teardown_reg`：仅注册未写 → 真；未注册 → 假。
2. `td_ensure_reg`：仅注册未写 → 假；注册并写后 → 真。
3. T-E.3 顺序断言：DEQUEUE 必须在任何 WPTR/RPTR 写之前；ACTIVE=0 时不得写 DEQUEUE。
4. 超时路径：ACTIVE 持续为 1 时记录 timeout 并继续关门铃/清指针。
5. 拒绝路径：分类器拒绝时计 `denied`，不中断后续步骤。
6. 幂等：连续两次拆除，第二次不重复写已静止队列。
7. 读回不符：计 `readback` 并汇总失败数。

**对称性评审**：每次新增或修改初始化写，评审必须回答“拆除时如何逆操作或为何无需逆操作”，并在 T-E.9 表或代码注释留痕（INV-A8）。

**真机验收**：拆除路径每步有 `N48R3LOG teardown:` 日志，结束时 `done fails=%u`；判据来自读回与持久日志，不以推测代替（INV-E1、INV-E4）。真机触发须遵守 INV-E3、PC-12 与部署纪律。
