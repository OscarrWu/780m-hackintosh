## 1. 编写意图与文档定位

本文档是阶段 3（内存与队列）的需求文档。本文档只含约束、验收标准、禁止事项与边界，不含实现方法；实现方法归《阶段3-技术方案》。

阶段 3 的目标（引自 13 册）：GPU 从"能上电"到"能干活"——UMA/GART/GPUVM 可用，doorbell/IH/CP/MES 打通，用户态可提交 PM4 并拿到 fence；完成标志为 store_magic compute 闭环且 magic 正确。

依 Q2 裁决：阶段 3 保持单一阶段，不拆分为多个阶段；§3.1 的阶梯子步是阶段内部的推进与回退粒度，不构成阶段拆分。

沿用 00-总体路线.md §0.2 四条最高原则与 §0.5 生产机六条（先只读后写入、证据先落盘、一次开机一次触发、人在场、不合盖、触发一律手动禁止 n48r3-auto=1）。阶段 3 追加：

## 3. 阶段范围与非目标

### 3.1 范围

1. **内存**：UMA carveout 基址/尺寸确认；GART 建立；GPUVM context0 页表；VMID 8 应用上下文（四级页表）。阶梯子步：mem → gart/context0 → VMID8。
2. **通知与队列**：doorbell 建立（wptr-shadow 先于 doorbell）；IH ring 建立与解码（仅作证据交付）；CP 队列（KIQ map_legacy_kq、compute queue）；MES ADD_QUEUE。fence 用 CPU 轮询（延续 C0.10 可见性契约，D4 裁决），不依赖 IOKit 中断路由（归阶段 4/5）。
3. **用户态 ABI**：N48R3 用户客户端最小面（D5 裁决）：BO 分配（UMA/GTT 区分）、CS 提交（PM4 IB）、fence 读取。n48r3test 是第一个消费者，其 mem|gart|doorbell|submit|compute 子命令为真实现（D2 裁决）。scanout 只留槽位指针指向 14 册；doDbgAdoptQueue=112 只登记编号；RADV 对接归阶段 5。
4. **compute 闭环**：用户态提交 store_magic compute，fence 返回且 magic 正确。

### 3.2 非目标

- 中断路由接入 IOKit（阶段 4/5）。
- RADV/Mesa 用户态驱动对接（阶段 5）。
- scanout/显示（14 册）。
- 通用 BO 管理框架沉淀（延续 C0.6 先例：最小提交基元可用，不沉淀通用框架）。

### 3.3 阶段 2 移交收口（入口前提）

阶段 2 已交付并归档（docs/archive/stage2-archive/），本阶段承接其边界：

- MES 门控已闭环：SET_HW_RESOURCES / QUERY 成功即阶段 2 完成标志；ADD_QUEUE 随 GPUVM 移入本阶段（C0.6 先例）。
- 最小提交基元边界：阶段 2 为 SDMA 拷贝/MES 验证实现的最小机制不沉淀通用框架；完整 GPUVM/GART/doorbell/IH/用户态 ABI 归本阶段。
- TMR 尺寸由 PSP 返回（阶段 2 对照 64MiB），本阶段沿用其返回值，不重新协商。
- 阶段 2 的 IORegistry 证据属性与 n48r3test 骨架延续使用；写路径 manifest 纪律（阶段 2 B1）继续有效。

### 4.0 前置定案：gfx1103 的 IP 版本组合

- GC IP = **11.0.1**（判定链：amdgpu_ucode.c:1488 固件名机制 + 本机固件归档 gc_11_0_1_* 全集 + nullarc README 旁证）。

- 完整 IP 组合：GC 11.0.1 / MMHUB 3.0.1 / OSSSYS 6.0.x / NBIO 4.3.x / PSP 13.0.4 / SDMA 6.0.1 / VCN 4.0.2。

### 4.1 PTE/PDE 位定义（amdgpu_vm.h:57-136）

VALID=bit0、SYSTEM=bit1、SNOOPED=bit2、TMZ=bit3、EXECUTABLE=bit4、READABLE=bit5、WRITEABLE=bit6、FRAG=bit7-11、PRT=bit51、PDE_PTE=bit54、LOG=bit55、TF=bit56、NOALLOC=bit58、PDE_BFS=bit59+；MTYPE：gfx9 走 bit57（AMDGPU_PTE_MTYPE_VG10_SHIFT）、gfx10 走 bit48（AMDGPU_PTE_MTYPE_NV10_SHIFT）。

nullarc 实测数值的位含义【推测】：root=phys|3=VALID|SYSTEM；PDE=phys|7=+SNOOPED；VRAM 页 PTE=0x71=VALID|EXECUTABLE|READABLE|WRITEABLE（无 SYSTEM/SNOOPED）。

**差异警示**：Linux root 层额外置 PDE_PTE（bit54，amdgpu_vm_pt.c:404-417），nullarc 实测未置位——macOS 侧是否置位需实机验证。指向 VRAM 的 PDE 地址需经 mc2pa 换算（gmc_v11_0.c:445-466；amdgpu_gmc.c:1199-1202）；gfx11 无 translate_further，PDB1/PDB0 无 BFS/TF 分支。

页表深度【推测】：32GB→vm_size 256TB→num_level=3（amdgpu_vm.c:2389-2431 推算链）→ PDB2/PDB1/PDB0+PTB 四级；PAGE_TABLE_DEPTH/BLOCK_SIZE 编程于 gfxhub_v3_0.c:290-334 setup_vmid_config（MMHUB 侧 mmhub_v3_0_1.c:313-332）。

**缓存一致性（对 13 册陷阱清单的修正）**：Linux 驱动**无 clflush**（grep 无命中）；CPU 更新路径一致性 = `mb()` + HDP flush（amdgpu_vm_cpu.c:132 amdgpu_device_flush_hdp）+ TLB invalidate。clflush 属 nullarc/macOS 环境手段，源码无依据；macOS 侧可见性契约（mb+HDP flush vs clflush）由技术方案裁决，需求文档只约束"写 PTE 后必须保证 GPU 可见性，手段须有依据"。

**实施侧定案（2026-11-15 对抗审查 A-04 澄清后回填）**：实现采用 clflush + `mb()` + HDP flush + TLB invalidate 的组合，其中 clflush 的依据为 nullarc 同机实测（PhxBringup.cpp:466-468："The GPU walker may not snoop CPU caches; every page-table/GART line written by the CPU is flushed"）。两者分工不同：HDP flush 保证设备侧已见，clflush 清洗 CPU cache 中的页表/GART 行（CPU 非一致写场景）；并存不冲突。"仅 HDP flush 是否足以覆盖 CPU cache 中的页表行"维持待收口实验项（一次只动一个变量，首轮不作为变量）。

### 4.2 IH 6.0.x 寄存器（osssys_6_0_0_offset.h，BASE_IDX 全 0）

IH_RB_CNTL=0x0080、RB_BASE=0x0081、RB_RPTR=0x0083、RB_WPTR=0x0084、WPTR_ADDR_HI/LO=0x0085/86、DOORBELL_RPTR=0x0087、RING1 系列 0x008c-0x0093、CHICKEN=0x018d、CNTL2=0x00c1。

- RB base 编程 [39:8]（ih_v6_0.c:273-275）。
- WPTR 两途径：writeback 内存（WPTR_ADDR + WPTR_WRITEBACK_ENABLE=1）+ MMIO RREG32_NO_KIQ（ih_v6_0.c:425-476）。
- IH doorbell index = doorbell_index.ih << 1 = 0x178<<1 = **0x2F0**【推测】（ih_v6_0.c:595-605）。
- 初始化 7 步（ih_v6_0_irq_init :321，:339-401）：CHICKEN.MC_SPACE_GPA_ENABLE→ih_doorbell_range→STORM_CLIENT→INT_FLOOD→MSI_STORM_DELAY→ring1 重定向（dGPU）→CNTL2 self-irq wptr force。
- OSSSYS 具体 revision（6.0.0/6.0.1/6.0.2）由 IP discovery 运行时决定，布局一致（单一头文件），不影响结论。

### 4.3 doorbell 表：GFX11 完全复用 NAVI10 表【客观观测】

soc21.c:494-528 全用 AMDGPU_NAVI10_DOORBELL_* 宏（amdgpu_doorbell.h:186-237）。关键 index：KIQ=0x000、HIQ=0x001、MEC_RING0-7=0x003-0x00A、MES_RING0/1=0x00B/0x00C、GFX_RING0/1=0x08B/0x08C、SDMA_ENGINE0/1=0x100/0x10A、IH=0x178。64bit doorbell 占两 index（实际编程 <<1）。doorbell BAR=BAR2（amdgpu_doorbell_mgr.c:210-211）。gfx ring doorbell=doorbell_index<<1（gfx_v11_0.c:1176）；MES/KIQ doorbell 经 PACKET3_MAP_QUEUES_DOORBELL_OFFSET（gfx_v11_0.c:424,452,478）。

> **两个"KIQ"概念辨析（对抗审查 B-01 澄清，2026-11-15）**：本表 KIQ=0x000 是 **GFX KIQ**（amdgpu 的图形管理通道，amdgpu_doorbell.h KIQ 宏）；而 MES 管理队列（nullarc 语境的"KIQ"，即 HIQ 语义的 MES ring）doorbell = MES_RING1<<1 = **0x18**，nullarc 同机实测背书，静态取证见 .trellis/research/阶段3-静态取证.md:281-319。两者是不同通道的 doorbell，实现侧 kMesDoorbellKiq=0x18 指 MES 管理队列，与本表 GFX KIQ=0x000 不矛盾。真机首轮按 R11 复核。

### 4.4 MC aperture 与 BAR 拓扑

- FB location：regMMMC_VM_FB_LOCATION_BASE=0x08ec / regMMMC_VM_FB_OFFSET=0x08d7（mmhub_3_0_1_offset.h）；GC 版 0x1678/0x15a7（gc_11_0_0_offset.h）。FB_BASE_MASK=0xFFFFFF，粒度 16MB（<<24）。本机 FB 窗口 0x8000000000 ⇒ BASE=0x800【推测】。
- **术语修正（对任务卡前提）**：gfx11 源码不存在 APER1/APER2 概念；只有 aper_base/aper_size（=BAR0）+ system aperture（GPU→系统内存窗口）。本文档采用 Linux 术语。
- aper_base/aper_size：默认=BAR0；APU x86_64 下 aper_base=carveout 物理地址、aper_size=real_vram_size（gmc_v11_0.c:704-709）。BAR0=256MiB 是硬件报告尺寸，源码无常量；可经 pci_resize_resource 调整（amdgpu_device.c:1186）。
- system aperture：LOW/HIGH=min/max(fb,agp)>>18、DEFAULT_ADDR=mc2pa(mem_scratch)>>12/44（gfxhub_v3_0.c:150-181；mmhub_v3_0_1.c:168-197）。寄存器：GCMC_VM_SYSTEM_APERTURE_LOW/HIGH=0x167d/0x167e、MM 版 0x08f1/0x08f2。
- AGP aperture 默认禁用（amdgpu_gmc.c:398-404）。

### 4.5 待取证项（源码静态无法回答，共 4 项）

1. OSSSYS 具体 revision（运行时 IP discovery 决定，不影响布局结论）。
2. gc_11_0_0 vs gc_11_0_3 完整差异清单（超范围；关键差异已列，本文档以 gc_11_0_0 为准）。
3. num_level=3 实机确认（推算链完整，标【推测】）。
4. clflush 在 macOS 侧的必要性（Linux 无依据；nullarc 实测用 clflush。实施侧已按 §4.1 定案采用 clflush+mb+HDP flush+TLB invalidate 组合，clflush 依据 nullarc 同机实测；"仅 HDP flush 是否足够"待真机收口实验）。

### 4.6 PM4 包形态取证（实施期补充，对抗审查 P-01 终审）

- **RELEASE_MEM（fence）包为 8dw**：TYPE3 语义 count=body-1，`PACKET3(PACKET3_RELEASE_MEM, 6)` 后须写满 8dw（包头+GCR control+DATA_SEL+addr_lo+addr_hi+seq_lo+seq_hi+**末尾补 0**）。依据：Linux gfx_v11_0.c:6065-6096（emit_fence，:6094 明确 `amdgpu_ring_write(ring, 0)`）；nullarc 同机实测 mesboot.c:534 `rm[8]={0xC0064900,0x06603514,0x40000000,fm_lo,fm_hi,0x77,0,0}`。少写 1dw 时 CP 会把下一 dword 当本包 body 吃掉，命令流错位。
- INDIRECT_BUFFER（0xC0023F00）等其余包形态以 §4.1/技术方案引用的 Linux 源码为准；包长语义"total = count + 2"（pm4_v11.h 注释）为正确口径。

## 5. 需求条目

条目编号沿用阶段 2 先例（组字母+序号）。每条须可追溯设计意图（INV-A1）。

### A 组：内存与 GPUVM

- A1 UMA carveout 确认：基址/尺寸以本机实测为准，与 MMHUB FB MC 窗口 0x8000000000-0x80ffffffff 对应关系明确（FB_LOCATION_BASE=0x800【推测】，真机首轮复核）。
- A2 GART/GPUVM 页表：PTE/PDE 位定义以 §4.1 为准（amdgpu_vm.h:57-136）；页表在系统内存；写 PTE 后必须保证 GPU 可见性，手段须有依据（§4.1 缓存一致性约束）。
- A3 GPUVM context0：gfxhub 寄存器全套（gfxhub_v3_0.c + gc_11_0_0_offset.h，§4.0）；root=phys|VALID|SYSTEM（nullarc 对照【推测】；Linux 另置 PDE_PTE bit54，是否置位需实机验证）；PDE=phys|VALID|SYSTEM|SNOOPED【推测】。
- A4 VMID 8 应用上下文：四级页表（num_level=3【推测】，§4.5-3），目录在系统内存；IB with VMID 8 可执行；写到达需 ACQUIRE_MEM（GL2 writeback，nullarc E7，需本机复核）；测试期 FAULT_DEFAULT=1（nullarc 对照，需本机复核）。
- A5 BO 放置策略约束：CP 写系统页经 VM 不可达时 BO 放 VRAM 池（nullarc E6 教训，需本机复核；技术方案裁决具体策略）。
- A6 早期地址约束：GART-VA 建立前，ring/MQD/fence/wptr-shadow 地址仅可用 MC aperture（BAR0+offset ↔ MC 地址，§4.4），不得用 GART-VA（nullarc E5，需本机复核）。

### B 组：doorbell 与 IH

- B1 doorbell index 分配以 §4.3 NAVI10 表为准（GFX11 复用【客观观测】）；wptr-shadow（WB+16）先于 doorbell 使能（nullarc E5，需本机复核）。
- B2 doorbell 写前可见性契约：sfence（BAR0 write-combining，nullarc E8 陷阱，需本机复核）。
- B3 IH ring 建立：寄存器偏移以 §4.2 为准（osssys_6_0_0_offset.h）；ring 解码作证据交付；fence 不依赖 IH（D4）。

### C 组：队列与用户态 ABI

- C1 KIQ 与 map_legacy_kq：RLC_CP_SCHEDULERS=0x30e8 + HQD me3/pipe1（nullarc E5，需本机复核；Linux 依据：gfx_v11_0.c:4100-4103 KIQ 编程 `(me<<5)|(pipe<<3)|queue | 0x80`，0x30e8 与 me3/pipe1/queue0+0x80 吻合）。
- C2 CP_ME_CNTL=0x01000000（CE_HALT 保持，nullarc E4b/E5 教训：写 0 致 PFP 挂 RCIU）。
- C3 MES ADD_QUEUE（COMPUTE）；MQD 初始化依据 gfx_v11_0_gfx_mqd_init（gfx_v11_0.c:4139）/ gfx_v11_0_compute_mqd_init（:4312），注册于 :7507-7513（nullarc E5 引用，行号已取证）。
- C4 用户客户端 ABI 最小面（D5）：BO 分配（UMA/GTT 区分）、CS 提交（PM4 IB，含 IB 高位符号扩展 0xffff8001 陷阱）、fence 读取。selector 契约 0..8+扩展位；doDbgAdoptQueue=112 只登记编号。
- C5 n48r3test 子命令 mem|gart|doorbell|submit|compute 为真实现（D2）。

### D 组：compute 闭环

- D1 store_magic compute：用户态提交 → fence 返回 → magic 正确；fence<1ms（Q5）。
- D2 阶梯子步开关：n48r3-gart / n48r3-mes / n48r3-queue 独立 kill switch，默认关闭。

## 7. 禁止事项与失败流程

### 7.1 禁止事项（沿用 13 册）

1. 不猜寄存器偏移（INV-A2）——一切以 §4 取证结果与 Linux 源码为准。
2. 不改 Apple 二进制（INV-A4）——只复制 vtable 替换槽位（本阶段预计无 vtable 改动，条款延续有效）。
3. 不跨阶段实现（§3.2 非目标）。
4. 不默认开启 boot-arg——阶梯子步开关默认关闭，手动触发。
