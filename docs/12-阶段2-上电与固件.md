# 阶段 2：上电与固件

## 0. 册头

### 0.1 编写意图

本册回答一个问题：**如何在不扰动显示链路的前提下，让 PSP、SMU、GFX、SDMA、MES 五个 IP 依次上电到 ready，把 GPU 从"固件点亮的冷状态"变成"驱动管理的已上电状态"。**

本册覆盖阶段 2 的全部内容，按统一模板重组、按全局统一说法修订。阶段 2 已于 2026-11-11 完成（V1–V18 全部 PASS、无 SKIPPED 项），本册记录当前事实与结案结论。

**术语约定（本册首现解释，后文直接使用）**：

- **触发**：指部署后由主 agent 手动发出命令，击发（执行）已武装（准备就绪、等待命令）的上电子步；开机自动执行上电的形态在开发阶段禁止。
- **武装门（arm gate）**：全局术语表已定义——驱动在执行上电子步前检查的前置条件门（准备完整性、证据通道、依赖子步完成等），不满足即拒绝并留下拒绝原因证据。
- **阶梯（stage ladder）**：`n48r3-stage=N` 控制驱动执行到第 N 子步，每步失败即停；preflight（起飞前检查）恒先于子步执行。
- **kill leaf**：每个 IP 子步的独立关闭开关（`n48r3-psp/smu/gfx/sdma/mes=0`），三态：缺省跟随阶梯、显式开、显式关。
- **回退**：通过 kill switch、boot-arg 或逆序 teardown（按上电相反顺序清理）把系统恢复到前一状态；不 GPU reset（保护显示）、PSP 留活。
- **manifest（写/读清单）**：驱动登记的"写过/读过的地址清单"属性，用于审计写路径与读路径。
- **黄金值表**：地址坐标（段号+偏移）的单一权威数据源，审计工具与被审代码读同一张表，杜绝两套坐标不一致。

### 1.3 完成标志

## 2. 上电顺序与子步

上电顺序（以 Linux 枚举序为依据）：

**SOS alive 自检 → ring → LOAD_TOC → SETUP_TMR → 17×LOAD_IP_FW（Linux 枚举序；MEC 扣减跳转表）→ AUTOLOAD_RLC（紧跟 RLC_G）→ SMU 0x3/0x2/0x16(1)**。

要点：

- SMU 的**效果标准为最终通过标准**：寄存器取 `GRBM_STATUS` 可读非零（默认 0、未上电实测全 0；观测/状态寄存器不门控；单次重查限定；**迟到显式错误不重查**）；
- SMU 版本读数缺失=条件通过（版本寄存器读不到不判失败，以效果标准为准）；
- SOS 不由驱动加载（平台常驻，经 C2PMSG_81 自检确认 alive）。

## 4. TMR 与内存布局

**TMR（Task Management Region，PSP 固件的工作内存区）**：尺寸由 PSP 返回（本机实测 **64 MiB**，与 nullarc 对照机同值——nullarc 数值仅作对照，本机已实测确认）；槽对齐 **1 MiB**、≤64 MiB 槽内子区。

内存布局规则：

- GOP guard 动态 + 顶部 no-write（保护 GOP 正在使用的显示内存）；
- 单 fw_buf（固件缓冲统一一份）；
- TMR 槽（对齐 1 MiB）；
- scanout 读数必须归一化为 carveout 偏移；
- sdma/mes 独立 grant；
- 零化区入不相交检查（各内存区两两不相交，防重叠破坏）。

- **首个写之前强制只读体检门**（值门控+读完成两层）。

## 8. 阶梯、开关与触发两形态

**阶梯/开关**：

- `n48r3-stage` N=子步深度（preflight 恒先于子步执行）；
- 五 kill leaf 三态（缺省跟随阶梯）；
- 依赖链含 mes→gfx；
- 组合矩阵 36 格。

**触发两形态**：

- **调试轮**：开机只跑 survey+体检（armed, not fired——已武装未击发），上电一律由主 agent 在部署后手动触发（同 boot 一次，F11 标记拒绝二次）；
- **触发只击发已武装子步**（从 psp 开始，`bringup_r3_from`），不重跑阶段 0–1；
- 武装门/准备/R3Io 不完整时拒绝并发布 `N48R3EVID-trigger-refused` 的 reason；
- **自动形态 `n48r3-auto=1` 日常化阶段前不启用，开发阶段（阶段 2–5）禁止启用**（见 00-总体路线.md §0.4 第 6 条）。

## 12. 风险与回退

**回退设计**：

- 五 kill switch + latch + 逆序 teardown（不 GPU reset、PSP 留活、**只复用已登记行、恢复 CP 暂停**）；
- `n48r3bringup=0`（驱动不加载，系统回纯原生）；
- 诊断转储按子步可用集；
任何真机失败按门铃/取指/回写三层定位，不再按轮次试错。

**风险条目**：

1. 显示链路零扰动是硬验收标准——上电全程屏幕由 GOP 扫描，内存布局以 GOP guard + 顶部 no-write 保护；
2. PSP 上电是 SWIP 序列前提（阶段 0 历史 panic 实证，见 10 册 9.2）——上电顺序以 SOS alive 自检开头；
3. 共享 HDP 缺窗口 fail closed——窗口发现只认 nbio_7_7_0 段 2，不可解析即准备失败，无段 0 回退；
4. 白名单外写=0 + 双 manifest + 黄金值表单一权威源——写路径全程可审计、可回放。

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 首次 `stage=5` SMU 判失败（R2/R3 合并轮） | SMU 效果标准误选 `RLC_STAT`（busy 位、0=空闲），判据语义错误；同批本机实测 `GRBM_STATUS=0x302c`（nullarc 对照机亦测得同值，仅作对照） | 修正为 `GRBM_STATUS` 可读非零；修正后第 3 轮 SMU/GFX/SDMA 通过 |
| 2 | R2/R3 MES 卡 S5 `SET_HW_RESOURCES` fence=0 | 旧代码 MC 地址问题 | MC 地址修复生效；后续 MES S−1/D1/EOP/S5.1 一次修复后门控 `expect-verify declared=55 hit=54 missed=0 extra=0` 达成 |
| 3 | R4 过程日志被 6 KiB arena 截断（r2/r3 同） | 证据缓冲容量不足 | 证据通道收敛至基座 n48log 2 MiB 环（arena 与 `stage2-log` 属性退役）；R5 起过程日志完整（7790 B / 89 行、0 次截断） |
| 4 | R5 `logstream` 子命令合法调用返回 rc=5，自动轮询落盘通道未生效 | 参数解析偏移一位 | 缺陷已修复（解析对齐“完整 argc/argv”约定、抽纯函数 `n48r3_parse_logstream_args`、新增 9 组主机断言 63→86 checks、工具侧测试固化进 `run_host_tests.sh`；kext 部署件不变）；取证者手动 `log` 导出，证据完整；第 6 轮复验通过 |
| 5 | 触发路径栈溢出风险 | 证据缓冲在栈上、二次触发、武装门缺失 | 修复：证据缓冲归实例、只击发已武装子步、武装门拒绝、构建期帧上限 |
| 6 | 收尾后复测 `info` selector 0 失败（rc=3，0xe00002c2），第一轮修复后复测引发内核 panic（2026-11-12） | UserClient OOL 输出形态与 MIG stub/内核契约冲突：①MIG stub 恒传非空 inband 缓冲且 `inband_outputCnt=0`，使首轮 OOL 分支不可达；②改 descriptor 前置判别（写法 A）后 `writeBytes` 作用于内核创建但未 `prepare()` 的用户内存描述符，命中 `IOGMD: not wired for the IODMACommand` 无条件 panic | 最终方案：照基座 `doReadLog` 形态改 **offset 分块读取**（scalarInput 传 offset、单次上限封顶 `NAVI48_UC_MAX_XFER`、scalarOutput 回传 total），弃用 OOL 路径；该形态约束已沉淀为项目 IO 约定（IO-8）。第 7 轮真机复验通过（info 首次真机成功） |

| IP | AMD GPU 内的独立功能硬件块（GC/PSP/SMU/SDMA/MES 等），各有版本号与基址 |
| ready | 某 IP 完成上电初始化、可接受命令的状态；五 IP ready 记为 `ready=0x1f`（位图） |
| SOS | PSP 的 Security OS 固件，平台常驻，驱动只自检不加载 |
| TA | Trusted Application 固件件，嵌入包内但不由驱动加载 |
| LOAD_TOC / SETUP_TMR / LOAD_IP_FW / AUTOLOAD_RLC | PSP 上电命令序列的各步：加载目录、设置 TMR、逐件加载 IP 固件、RLC 自动加载 |
| MEC 扣减跳转表 | LOAD_IP_FW 枚举序中对 MEC（微码引擎）件的序号扣减规则 |
| RLC / RLC_G | Run List Controller（图形微码调度器）；RLC_G 为其 GFX 件 |
| IMU | GFX 的 Instruction Microcode Uploader，GFX 上电前置 |
| PMFW | 平台管理固件（SMU 固件的平台侧），本机由平台预加载【推断】 |
| 邮箱（mailbox） | 驱动与 SMU/PSP 通信的寄存器消息通道（C2PMSG 系列） |
| C2PMSG_81 | PSP 自检应答寄存器，用于 SOS alive 自检 |
| GRBM_STATUS | 图形寄存器块主状态寄存器；SMU 上电效果标准取其可读非零 |
| RLC_STAT | RLC 状态寄存器；其 busy 位 0=空闲，曾被误选为 SMU 效果标准（失败模式 #1） |
| SMN | System Management Network，GPU 的系统管理寄存器网络，经间接窗口访问 |
| HDP | Host Data Path，CPU 直访 GPU 内存的地址翻译路径；PSP/SDMA/MES 共享其窗口 |
| nbio_7_7_0 段 2 | HDP 窗口所在 discovery 段（NBIO 7.7.0 IP 的第 2 段） |
| MMHUB FB_LOCATION / FB_OFFSET | 显存（FB）基地址与偏移寄存器，TMR 地址角色的来源 |
| MQD/HQD | 队列描述符（Memory/Host Queue Descriptor）；MES 语境下改 MC 形态 |
| MC 形态 | 队列/门铃经 Memory Controller 地址呈现的形态（区别于 MMIO 形态） |
| 调度环 | MES 的调度命令环（kernel scheduler ring），SET_HW_RESOURCES/QUERY 经其应答 |
| expect-verify | 期望-核对机制：声明期望行数（declared）、实际命中（hit）、缺失（missed）、多余（extra） |
| armed, not fired | 已武装未击发：调试轮开机只武装不执行，等待主 agent 手动触发 |
| latch | 失败锁存：某路径失败后本 boot 内锁存关闭，不再重试 |
| teardown | 按上电相反顺序清理（逆序拆除）；本项目不 GPU reset、PSP 留活 |
| n48log | 驱动内过程日志基座设施：2 MiB 环形缓冲 + user client 读取接口 |
| logstream | `n48r3test` 的子命令：配合 launchd 轮询器把 n48log 环持续落盘到 `/var/tmp/n48r3-driver.log` |
| fence | 完成信号值：GPU 执行完毕后回写，CPU 轮询确认（阶段 3 起大量使用） |
