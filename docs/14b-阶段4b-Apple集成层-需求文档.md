## 1. 编写意图与文档定位

### 1.1 意图

阶段 4b 的目标不是自写图形加速器，而是把 Apple 既有加速框架接到真实的 780M 硅上：让「TTL 服务对象 → Hardware 对象 → VMM 对象 → 通道/队列 → 加速器」这条链路建立在阶段2/3 已验证的固件、内存、队列之上，并由阶段4a 已验收的显示宿主提供画面。本文档把"接线"的边界、取证义务与失败后果说清楚。

### 1.2 链路骨架（本文档的叙述主线）

WindowServer → `IOGraphicsAccelerator2` → `AMDNavi21GraphicsAccelerator`（`newHWInterface`）→ `AMDNavi21Hardware`（Ventura 268 槽）→ TTL 服务对象（43 槽）→ GC/MM Hub（39 槽）→ `AMDHWVMM`（82 槽）→ `programAndInvalidateVM` → HDP flush。旁路调用者：`AMDRadeonX6000PPLIB` 经 `getTtl` 读取 RTS 表（`+0x5b0..+0x940`）驱动功耗状态。

### 1.3 定位与读者

读者为：主 agent（裁决与验收）、技术方案作者、实施程序员、上机操作者。文档只回答"必须满足什么、如何判定、什么不许做"。任何单点成功（例如服务出现但合成未走加速器）都不构成"4b 完成"，唯一判词见 §6.2。

## 2. 最高约束原则

### 2.1 全局原则（引用，不重述）

- `src/docs/00-总体路线.md` §0.2 四条：遵循原始设计意图、最小侵入、失败可回退不 panic、性能保障。
- `src/docs/00-总体路线.md` §0.5 六条：只读先行、证据落盘、一次开机一次触发、人在场、人工不合盖、手动触发（禁 `n48r3-auto=1`）。

### 2.2 本篇追加原则

- **P4B-1 TTL 是唯一硅抽象边界。** Apple 侧需要的一切硬件信息必须从 TTL 契约取得；不得在 hook 层绕过 TTL 直读/直写 MMIO（`INV-A1`、`IO-3`）。
- **P4B-2 不改 Apple 二进制。** 只允许内存中复制 vtable、替换目标槽、改 vptr；禁止改磁盘 kext 与内核缓存（`INV-A4`、`PC-2`）。
- **P4B-3 槽位双证。** 槽号、页内偏移、结构偏移必须同时有静态证据与运行时探针；只有静态证据不得 patch（`INV-A2`、P-01～P-03）。
- **P4B-4 失败回到 4a 态。** 任一环节失败即卸载加速器并回到 4a 已验收显示态，不 panic、不重试（原则三、`INV-B3`/`INV-B4`、`PC-12`）。
- **P4B-5 加速器激活属不可逆级操作。** 按"只读 → 干跑（patch 不激活）→ 非生产机 → soak"阶梯推进，逐步人工触发并留证据（`BV-11`、`BV-13`）。

## 3. 范围与非目标

### 3.1 范围

1. TTL 替身对象：43 槽对象创建、固件目录接受、状态类槽与阶段2/3 真实状态机映射。
2. 槽位取证与 hook：Ventura 侧 TTL/Hardware/VMM/Registers/Hub 的槽号与页内偏移、hook 安装与惰性 patch。
3. Hardware/VMM 偏移表：GFX12 偏移替换为 GC 11.0.1 偏移，并保持写路径唯一。
4. xlat11 翻译层：覆盖扩展、拒绝路径保持、真机抓包验证。
5. 加速器激活：`LoadAccelerator` 通路、`IOGraphicsAccelerator2` 出现、WindowServer 走加速器合成。
6. 共存与回退：PPLIB 第二调用者、Wi-Fi 干扰回归、回退开关。
7. 证据与用户态工具、提交卫生。

### 3.2 非目标

- 自写加速器或自建 `IOGraphicsAccelerator2` 实现（调研 §3 记为高侵入备选，不纳入需求）。
- Metal 驱动、RADV、图形栈完整功能（阶段5）。
- 修改 Apple 二进制、持久化 patch、跨 boot 缓存偏移。
- Tahoe 真机验证（仅保留可编译；版本差异只作登记）。
- DCN 显示宿主、DCN 翻页接管、自建 AGDC、背光（归阶段4a）。
- 外接显示器、多 GPU、多加速器实例。
- TTL 中本机无对应硬件的槽（HDCP、AUC、FP、XGMI、RAP）：对象内需有槽位，但本篇不提功能需求，未实现槽返回"不支持"。
- 向 Apple TTL 注入固件目录（选项 B）：仅在 O1 证据闭合后经用户重新裁决才可评估，非本篇交付项（§4.2）。

### 4.2 O1 裁决记录（SMU `fw_type=18`）

**事实**（横切调研 §3.1～§3.4）：Linux 7.2.0 中 `fw_type=18` 是 PSP `LOAD_IP_FW` 的 `GFX_FW_TYPE_SMU`；但 Phoenix（SMU 13.0.4）的 pptable 未挂接 `init_microcode`，宏在接口为空时直接返回 0，因此 Linux 的 Phoenix 路径不请求 `smu_13_0_4.bin`，也不会发 18；证据索引判定该固件不存在（与 psp/报告.md 存在性记述冲突，未决）；nullarc 的"SMU 0x16"实为 `PPSMC_MSG_EnableGfxImu` 消息而非 fw_type，其不加载 18 是实现事实而非"不需要"的证明；阶段2 已记录 ready=0x1f（仅覆盖 5 IP 上电自检）。

**用户裁决（a_plus）**：**维持现状（不加载 18）为默认**；4b 开工前完成横切调研 §3.6 五项证据闭合（→ P4B-14）。正文任何条目不依赖 18 的加载或不加载；4b 的电源管理相关行为沿用阶段2 已成立的状态，不因 4b 修改 PSP 序列。若五项闭合后的证据支持补载（选项 B）或可配置诊断开关（选项 C），须先提请用户重新裁决、另立条目，不在本篇内悄悄扩范围。

## 5. 需求条目

编号为组字母＋序号。每条三件事：需求（约束）、可执行验收、设计依据；验收的证据形态统一见 §6。**组内总约束**先于条目，是组内跨条不变量。

### A 组：TTL 对象

**组内总约束**：替身 TTL 必须在抽象边界之下完整履约；未实现的槽返回 `kTtlUnsupported` 并记录，不得返回假状态、不得崩溃。

- **A1 TTL 替身对象**：按 43 槽契约生成 vtable，对象 2880 字节，以 gfx1103 语义命名（如 `NaviR3Ttl`），不得沿用 rdna4 命名的 `Navi48Ttl` 而不做适配；`getTtl` 返回本对象；未实现槽显式返回"不支持"（取值沿用 F1-03 记录的 Apple 未实现槽 stub 形态 `0xE00002C7`，不自行发明值），不得返回空指针；不得进入 Apple TTL 内部函数。**验收**：vptr 落在自有 vtable 内、逐槽调用无空指针、符号审计无 Apple TTL 内部命中。**依据**：F1-01～F1-04、F1-15、F1-17、F1-07、`INV-A7`、Apple集成层调研 §3.2。
- **A2 固件目录接受**：`setFirmwareDirectory`（slot8）接受 Apple 传入的目录指针并记录，返回成功（`kTtlOk`）；不调用 Apple 的 84 项设备 ID 查表、不读写私有字段（如 `+0x970`）；不得伪造"目录填充成功"。**验收**：调用被记录、`initialize` 不再因目录缺项失败、日志无 `populateFirmwareDirectory` 调用记录。**依据**：F1-06、F4-01、Apple集成层调研 §3.3 选项 A。
- **A3 状态类槽真实映射**：`queryFwLoadingStatus`(21)、`queryEngineQueueState`(38)、`notifyHardwareState`(40) 映射到阶段2/3 真实状态机，禁止常量假装"已加载"。**验收**：未加载时返回未就绪、加载未完成前加速器不推进、跃迁有日志；负向测试覆盖"状态未就绪"。**依据**：F7-04、F7-01、F1-04、F1-05、`INV-E4`。
- **A4 寄存器基址与段数**：`queryHwBlockRegisterBase` 返回真实块基址（7 次调用）、`getHwipSegmentCount` 返回 6、布尔槽真/假返回 1/2（Apple ABI 约定，F1-05）。**验收**：7 组基址与 Linux discovery 一致并逐项落盘。**依据**：F2-06、F1-04、F1-05。
- **A5 内存信息槽**：`getLocalMemoryInfo`/`getNonLocalMemoryInfo`/`getGartTableAddress` 返回阶段3 已建立的 VRAM/GART 真值，不另建映射。**验收**：返回地址与阶段3 GART 基址一致、无新增分配。**依据**：F1-04、F7-03。
- **A6 不依赖 Apple TTL 内部实现**：选项 A 口径下不调用其目录填充函数、不读写私有字段（如 `+0x970`）。**验收**：符号审计与运行时日志无命中。**依据**：F1-06、F1-07、Apple集成层调研 §3.3。
- **A7 PPLIB 第二调用者兼容**：保持 PPLIB 经 `getTtl` 读 RTS 表的能力，返回契约稳定、不返回半初始化对象；PPLIB 初始化失败不得使内核挂起。**验收**：PPLIB 路径日志有 `getTtl` 且状态一致；30 分钟无 panic、无新增 PSP 环错误。**依据**：F1-08、F4-04。
- **A8 初始化一次与版本闸**：`initialize` 只在创建后调一次；版本/规格不匹配即 fail-closed 并保留原槽。**验收**：重复初始化被拒；不匹配场景无 patch。**依据**：F1-07、F1-09、`INV-D3`。

### B 组：槽位取证与 hook

**组内总约束**：槽位号、delta、页内偏移三者缺一不可且必须**成组来自同一次 Ventura 实测**；不得混用 Tahoe 与 Ventura 的值。整套常量（寄存器影子缓存、VMM invalidate、VM context、GART 镜像、channel、ring、KIQ 等）成组重测，不是只换"三项 hook"常量。

- **B1 TTL 侧 hook 常量 Ventura 化**：`[266]=0x1c10`、`[268]=0x29a0`、`[269]=0x1630`，页内偏移 `0xc10`，delta `−0x5e0`/`+0xd90`，槽数 270；Ventura 与 Tahoe 的 delta 符号相反。**验收**：安装后 `getTtl` 命中并返回本对象地址；三锚点字节校验通过。**依据**：F1-11、F1-10、F2-12。
- **B2 Hardware 侧表长与移位**：按 `AMDNavi21Hardware` 268 槽设表长与复制词数（268+2）；四移位按 Ventura 修正（`187→191`、`191→195`、`247→250`、`248→251`）。**验收**：复制表除目标槽外逐项相等；移位槽有静态+运行时双证。**依据**：F2-01～F2-03、F2-12。
- **B3 同号槽位修正**：寄存器写 36、HDP 刷新 62、取 VMM 93、注册通道 102；VMM `36/37/40/41/71`；Hub `35/36/37`；寄存器表锚点 35（48 槽）。**验收**：每个被 hook 的槽各有一行静态证据与一行运行时证据。**依据**：F2-02、F2-07、F2-12。
- **B4 运行时槽位探针**：复用阶段0 探针完成 P-01（TTL 三锚点）/P-02（Hardware 268 槽关键槽）/P-03（VMM 82 槽 36/37/40/41/71），两次 boot 交叉，结果落 `N48R3EVID-SLOT-*`。**验收**：两次偏移一致且等于静态表；不一致即停。**依据**：F1-12、Apple集成层调研 §4、`INV-A2`。
- **B5 安装顺序**：TTL 先、Hardware 后、翻译层在线、VMM 惰性 patch 后再激活；顺序与 `AMDHardware::init` 真实调用序一致。**验收**：日志次序为取 TTL → 初始化 TTL → 配置寄存器基址 → 读芯片版本 → 硬件工作区修正（workarounds）→ 分配内存/GART/VMM/寄存器/Hub。**依据**：F2-05、F4-06、F1-07。
- **B6 VMM 惰性 patch**：hook `getVmm`，首次取得 vtable 时复制并替换 71 槽，屏障后改 vptr；失败必须拒绝返回，不得返回半 patch 对象或原对象冒充。**验收**：每次 boot patch 计数恰为 1；失败样本具名拒绝并留日志。**依据**：F4-05、F4-06、`INV-B2`。
- **B7 锚点不符即停（安装几何校验）**：安装前做几何校验——目标地址落在内核半区、与锚点的 delta 等于常量、页内偏移等于常量；锚点字节、槽数、结构偏移任一校验失败即拒绝 patch 并具名报错，不退化到猜测。**验收**：人为改动任一常量/锚点后拒绝执行且无任何写发生、原槽保持不变。**依据**：F2-12、Apple集成层调研 §2.3、`INV-A2`、`INV-B1`。
- **B8 不改磁盘与不持久化**：patch 仅存在于内存；不写 kext/内核缓存、不跨 boot 复用偏移。**验收**：运行前后磁盘 kext 哈希不变。**依据**：`INV-A4`、F1-12。

### C 组：Hardware/VMM 偏移表

**组内总约束**：每一条偏移与位定义都必须有 Linux 出处；查不到出处就不写码（`PC-7`）；TTL 之外不得新增 MMIO 直写，显示相关寄存器访问仍归 4a（`LY-7`、`LY-11`）。

- **C1 偏移逐条取证**：偏移表每条给出 GC 11.0.1 对应头文件行号（`gc_11_0_0` 或经 P4B-06 确定的头），不得沿用 GFX12 地址。**验收**：表内每条有出处行号，抽样复核语义正确。**依据**：F6-02、F6-05、I-01、`PC-7`。
- **C2 HDP 刷新**：`flushHDPCache` 使用 GFX11 正确地址与语义，轮询有上限并可返回错误。**验收**：刷新后读回可见；超时返回错误、不空转。**依据**：F4-05。
- **C3 VMM 失效提交**：`programAndInvalidateVM` 按 GFX11 语义实现（invalidate-ACK 位在 GFX11/12 上语义不同，沿用 GFX10 会内核空转无日志），失效应答等待有界。**验收**：应答到达或超时返回，全程无挂起、无静默空转。**依据**：F4-05、`INV-B3`。
- **C4 写路径唯一**：所有 MMIO 写仍经 36 槽单一路径（`regWrite`(36)＋`queryHwBlockRegisterBase`(11)），不新增第二写点、不建第二套影子缓存；跨边界写遵循"写→屏障→刷新→读回"。**验收**：全仓 MMIO 写点计数为 1，新增即 FAIL。**依据**：F2-07、F2-06、F2-11、`IO-3`、`INV-C1`、`INV-C2`。
- **C5 GART/通道/队列同型**：与 `map/unmapToGart` 既有 ABI 一致，不把对照项目平台数值固化进本机路径。**验收**：与对照基座差异仅平台相关项且逐条说明。**依据**：F1-03、`PC-2`、`PC-8`、`INV-A6`。
- **C6 偏移表登记**：偏移表与代码分离、集中登记、可审计；新增条目必须由生成器或对照表产出。**验收**：登记表存在且与代码一致。**依据**：`INV-A5`、`LY-9`。
- **C7 上层 GFX10 捷径清单**：Apple 上层写死 GFX10 地址的热路径登记成表，逐个说明如何被 hook/偏移表覆盖。**验收**：清单在档；新增捷径有告警。**依据**：I-02、Apple集成层调研 §2.2。

### D 组：xlat11 命令流翻译

**组内总约束**：生成器是单一事实源；缺源、歧义、字段畸形一律失败退出，不写半成品；语义冲突降级 `UNKNOWN` 并记 provenance。

- **D1 xlat11 单一事实源固定**：固定使用 Mesa `4519cc56…` 与 Linux `v7.2` 两份上游（物料在 `evidence/src/`），生成器重跑零差异。**验收**：重跑无差异、provenance 可查。**依据**：F5-05、14 册 §4.3。
- **D2 六项缺口转实施项**：全量覆盖、真机抓包 golden、reused 自动探测、DCC→FDCC 语义、`_INDEX` 接受集、unknown 类，六项各列独立判据。**验收**：六项各有 V 表行或实施项证据，禁止"整体可用"式概括。**依据**：F5-07。
- **D3 拒绝路径不放宽**：容量上限保持 8；越界返回容量错误、旧管线拒绝、未知寄存器标 UNKNOWN，不得降级为直通。**验收**：越界被拒且哨兵完整；拒绝类样本有计数。**依据**：F5-03、F5-04。
- **D4 规则逐条审查**：七类规则（`31-2-12-11-7-0`）与 9 条复用规则逐条给出源/目标字段位置。**验收**：种子行逐行有出处，抽检可复算。**依据**：F5-02、F5-04。
- **D5 真机抓包 golden**：入口设容量有界环形缓冲，抓包离线比对，抓包不改变命令流。**验收**：抓包与离线比对全等，或差异逐条解释并归档。**依据**：F5-07（第 2 项）、I-04、`INV-F5`。
- **D6 缺源即失败**：缺源、地址歧义、字段畸形时非零退出且不写半成品。**验收**：缺源构建失败；仓内路径生成成功且零差异。**依据**：F5-06、P4B-05。
- **D7 子模块边界**：翻译层为独立子模块，驱动只含其对外头、不重复编译其源。**验收**：构建日志无重复编译，host 测试可独立运行。**依据**：`LY-9`。

### E 组：加速器激活

**组内总约束**：激活是最后一步，且只在前置全部成功后才触发；失败即回退到 4a 的软件合成，不得半激活。

- **E1 激活开关**：激活由 `LoadAccelerator` 布尔属性驱动，默认跟随阶梯、可关；关时系统完全可用。**验收**：关闭时加速器不出现且正常到桌面。**依据**：`PC-11`、14 册 §4.5、F4-02。
- **E2 加速器服务出现**：`IOGraphicsAccelerator2` 实例出现在注册表。**验收**：注册表查询命中，硬件接口与槽位符合 B 组结论。**依据**：F3-07、A-01、14 册 `:290-296`。
- **E3 加速路径计数**：翻译入口计数与提交次数同源可核。**验收**：计数单调且与帧提交同量级；无"提交未翻译"空转。**依据**：14 册 §6.2、A-03。
- **E4 WindowServer 走加速器合成**：合成走正统加速器路径，不退回 CPU 全量拷贝。**验收**：加速提交统计随窗口活动增长，无 CPU 全拷贝兜底日志。**依据**：14 册 §6.2、A-02。
- **E5 Wi-Fi 无回归**：激活后无线驱动行为不劣化。**验收**：30 分钟内连接稳定、连通性抽测无中断；中断即 FAIL 并回退。**依据**：F4-03、A-05。
- **E6 失败链回退**：任一初始化步骤失败即卸载加速器并回到 4a 显示态，不重试。**验收**：故障注入后回退成功、系统可用、latch 置位。**依据**：F4-02、`INV-B3`、`BV-14`。
- **E7 不新增私有 selector**：不在既有 ABI 槽附加自定义语义，不在增长区外新增编号。**验收**：外部方法编号无冲突、新增接口清单为空。**依据**：F3-08、`IO-8`。

### F 组：证据与用户态

**组内总约束**：证据先落盘再动作；四类承载（过程日志/判据证据/失败转储/证据键索引）不混写；用户态接口只增不改（`IO-2`、`IO-7`、`IO-8`、`INV-E1`/`INV-E3`）。

- **F1 证据键登记**：槽位、TTL、翻译、加速器、健康五类证据统一前缀并集中登记。**验收**：每次触发产物落 `evidence/` 且索引有登记；每个 V 行能指到具体证据键。**依据**：`IO-2`、`IO-7`、`INV-F1`。
- **F2 探针与日志分级**：槽位调用序用 NOTE 级日志；替身各槽内加 NOTE 日志取得首启调用序（不改变返回值）；过程日志复用统一设施；判据证据走独立属性；不建私有缓冲。用户态诊断子命令族沿用 4a 的 `n48r3test` 框架：`slot`（槽位/锚点/hook 状态）、`ttl`（TTL 逐槽探测）、`xlat`（翻译计数与错误）、`accel`（加速提交统计）、`golden`（抓包比对结论）。**验收**：日志样本与容量上限落盘；`n48r3test slot/accel` 可读钩子状态、`n48r3test xlat` 可读翻译计数与最近错误。**依据**：`IO-7`、I-03、4a F2 子命令先例。
- **F3 触发记录**：每次真机触发记录人工动作、时间、启动参数、结果，由主 agent 执行。**验收**：触发记录可回溯到证据键。**依据**：`BV-13`、00 册 §0.5。
- **F4 交付物落点与形态**：证据与日志落 `evidence/` 或 `tmp/`，目标机用 `/var/tmp`，不落系统临时目录；UserClient 复用基座 inband/offset 分块，不引入 OOL 等新形态。**验收**：产物路径符合约定；接口形态评审通过。**依据**：`BV-15`、`IO-8`。

### G 组：安全网、开关与失败停

**组内总约束**：安全网只做"保命与可回退"，不承担"修功能"；任何安全网动作不得导致 panic（原则三、`INV-B3`）。

- **G1 前置门禁**：锚点字节、槽数、偏移三项任一不符即不 patch、不激活并指名原因。**验收**：三项各注入一次不符样本均被拒。**依据**：`INV-B1`、`INV-B2`、F2-12。
- **G2 惰性 patch 原子性**：先复制、再替换、屏障后改 vptr；失败即丢弃副本。**验收**：失败注入后原 vtable 未被触碰（哈希不变）。**依据**：`INV-A4`、F4-06。
- **G3 失败即锁**：加速器失败置 latch，重启前不自动解除，解除需新证据。**验收**：latch 可读且不自动清除。**依据**：`PC-12`。
- **G4 有界等待与不 panic**：刷新、失效应答、加载轮询全部有界，失败返回具名错误。**验收**：故障注入矩阵无 panic、无挂起。**依据**：`INV-B3`、`INV-B4`、原则三。
- **G5 回退目标明确**：回退目标为 4a 显示态，通过启动参数或 kill file 达成。**验收**：回退后画面正确、系统可用。**依据**：14 册 §7、P4B-01。
- **G6 PPLIB 崩溃防护**：`getTtl` 返回契约稳定；初始化失败时 PPLIB 得到明确失败而非挂起。**验收**：失败注入后系统可启动、无 panic。**依据**：F4-04、A7。
- **G7 不触碰禁止域**：不写 SMU 电源/时钟/电压策略、不写非易失存储区、不绕过固件目录语义；诊断开关不得解锁禁止域；部分初始化设备不得被电源管理挂起（睡眠请求拒绝并记录）。**验收**：代码审计无禁止域写入。**依据**：`IO-5`、`INV-D6`、P4B-07。

### H 组：测试

**组内总约束**：测试先于真机；每级真机动作必须有前置 PASS；门禁不得降级（`BV-9`）。

- **H1 host 测试**：TTL 槽分派、hook 锚点校验、翻译 288 例与容量越界、fuzz、VMM 表构造均为可注入纯逻辑，可无硬件运行；每个必需输入配负向测试。**验收**：全量 host 测试通过、植入缺陷被捕获。**依据**：`BV-2`、`BV-3`、F5-03、`INV-F2`。
- **H2 双目标构建**：rdna3 与 rdna4 均构建通过（rdna4 只要求编译）。**验收**：两份构建日志。**依据**：`BV-6`、`PC-3`。
- **H3 生成物纪律与槽位表评审**：翻译表与偏移表由生成器产出、不手改、重跑零差异；静态槽位表＋运行时探针结果交叉评审，任何不一致即停。**验收**：重跑后代码树无差异；评审记录与探针记录同时入档。**依据**：`INV-A5`、F5-05、B1/B4、`BV-5`。
- **H4 故障注入**：锚点不符、目录缺项、槽号不符、失效应答超时、加载失败五类各一例。**验收**：五例结果表全部"停或回退"且无 panic。**依据**：`BV-5`、`BV-11`、F4-01。
- **H5 真机阶梯**：只读探针 → TTL 替身（不激活）→ 单 hook → 全 hook → 激活，五级逐级推进、不可越级，逐级人工触发、失败即停。**验收**：每级证据齐全，上一级未过不进下一级。**依据**：`BV-11`、`BV-13`、P4B-5。
- **H6 性能守门与 soak**：性能守门取 14 册 §6.3 的四项指标（fence 完成延迟 <1ms、`vkprobe` 256/256、窗口拖动无可感知卡顿、90Hz 实际扫描无降档），并检查加速路径不引入 CPU 全量回读；soak 按同节连续 ≥30 分钟 × 2 次开机、独立计数。**验收**：四项指标与两次开机结果分别归档（对应 V4B-14、V4B-15）。**依据**：14 册 §6.3、00 册 Q4/Q5。

### I 组：提交卫生

**组内总约束**：一次提交只对应一张任务卡与一组证据；不可追溯的改动不提交。

- **I1 一卡一提交**：提交信息含改动、通过标准、回退方式。**验收**：每个提交可在验收记录中回溯到一个需求条目；单提交只含一个逻辑改动。**依据**：`PC-10`、00 册 §9.3。
- **I2 每提交附证据**：证据键或日志随提交说明给出。**验收**：证据指针可解析到实际产物；缺失即不合并。**依据**：`PC-10`、`IO-2`。
- **I3 复用代码标注**：标注来源与许可证；不把对照项目平台数值当本机真值。**验收**：仓库内检索可定位每个复用片段的来源标注；平台数值均标注"待本机复核"。**依据**：`PC-8`、`INV-A6`。
- **I4 不提交敏感与产物**：不提交固件、Apple 捕获件（含反汇编导出、EDID/DPCD 原始件）、构建产物。**验收**：提交清单中不含上述类型文件。**依据**：`PC-9`。

### 6.2 唯一判词

**只有 V4B-1～V4B-19 全部 PASS，且性能守门与 soak 均通过**，才允许宣称"4b 完成"。任何单点成功（服务出现、计数增长）都不构成完成；不允许"基本可用"等模糊结论。

### 6.3 失败预案

| 失败模式 | 识别 | 处置 | 回退目标 |
|---|---|---|---|
| 锚点/槽位不符 | 前置门禁拒绝 | 不 patch、不激活，记录并上报 | 4a 显示态 |
| 目录缺项致初始化失败 | 初始化日志失败码 | 按失败链卸载加速器 | 4a 显示态 |
| 失效应答不来 | 有界等待超时 | 返回错误、latch、卸载 | 4a 显示态 |
| 加速器挂起（无 panic） | 帧提交停止、计数停滞 | 外部观察确认后手动关闭激活回退，内核侧不做自动看门狗 | 4a 显示态 |
| Wi-Fi 中断 | 网络抽测失败 | 立即关闭激活并复测 | 4a 显示态 |
| 睡眠请求到达部分初始化设备 | 系统睡眠请求 | 拒绝并记录，不挂起 | 4a 显示态 |
| PPLIB 初始化失败 | PPLIB 日志＋系统挂起迹象 | 阻断 PPLIB 路径、回退 | 4a 显示态 |

### 6.4 soak 与性能守门

soak 为连续 ≥30 分钟 × 2 次开机，两次独立计数、不合并。通过标准结构取 14 册 §6.2（TTL 对象创建、槽位运行时验证、xlat11、hook 安装、加速器激活五条）；soak 阶梯与性能守门指标取同册 §6.3（fence 完成延迟 <1ms、`vkprobe` 256/256、窗口拖动无可感知卡顿、90Hz 实际扫描无降档），不得以"加速路径另有一套指标"为由自拟口径。

## 7. 禁止事项与失败流程

### 7.1 禁止事项

1. 禁止野路子与绕过（原则一）：不得以"先能跑"为由跳过 TTL 契约直读硬件。
2. 禁止无出处改动（`INV-A1`、`PC-7`）：偏移、位域、槽号必须有 Linux/Mesa/二进制出处。
3. 禁止猜测槽位与偏移（`INV-A2`）；只有静态证据不得 patch（P4B-3）。
4. 禁止未标注的未验证结论（`INV-A3`）：一律标"待取证"并归 P 组或实施项。
5. 禁止修改 Apple 二进制、禁止持久化 patch（`INV-A4`）：只复制 vtable 替换槽位。
6. 禁止破坏写路径唯一与提交顺序（`IO-3`、`INV-C1`、`INV-C2`）。
7. 禁止触碰电源与时钟禁止域（`IO-5`）。
8. 禁止引入崩溃风险（`INV-B3`、`INV-B4`）：无界等待、panic、强制断电不得作为常规路径。
9. 本篇特有：禁止自写加速器替代 Apple 框架；禁止为通过验收放宽拒绝路径或降低容量上限；O1 已裁决维持现状为默认，**B/C 升级须先完成五项证据闭合（P4B-14）并经用户重新裁决，在此之前禁止新增 `fw_type=18` 加载步骤**；禁止用常量伪造固件/队列"已加载"；禁止手改生成表绕过 P4B-05；禁止混用 Tahoe 与 Ventura 槽位常量（B 组总约束）；禁止重复实现 4a 的显示宿主、AGDC 与 DCN 翻页。

### 7.2 失败流程（五步）

1. **记录**：保留日志、证据键、触发记录，不改写历史。
2. **停机**：置 latch、关闭激活开关、停止重试。
3. **回退**：回到 4a 显示态并确认系统可用。
4. **回顾**：定位失败点（锚点/槽位/偏移/状态/竞态），形成结论与待取证项。
5. **不掩盖**：失败结论进入证据与文档，不删除记录、不降级判据后再宣称通过。

## 9. 术语

| 术语 | 含义 |
|---|---|
| TTL | Apple 的硅抽象服务对象接口，43 槽，是 Apple 侧访问硬件的唯一契约 |
| 替身 TTL | 本项目自有、实现同一 43 槽契约、替换 Apple 实现的对象 |
| 槽位/页内偏移 | vtable 中第 N 个函数指针 / 该指针在符号页内的字节偏移 |
| delta | 两版本 vtable 对应槽的字节差 |
| 惰性 patch | 目标对象尚未创建时不预替换，首次取得其 vtable 时复制并替换 |
| 几何校验 | hook 安装前的三项检查：目标地址落内核半区、delta 等于常量、页内偏移等于常量 |
| `kTtlUnsupported` | 替身 TTL 对未实现槽的显式"不支持"返回值；取值沿用 F1-03 记录的 Apple 未实现槽 stub 形态（`0xE00002C7`），不自造值 |
| kill switch | 独立回退开关；4b 优先沿用 4a 既有开关（`n48r3bringup=0`、`n48r3-dcn=0`、kill file），如确需 4b 专属开关（如 `n48r3-ttl=0`），须按 `PC-11` 登记命名与三态语义后才可使用 |
| 翻译层（xlat11） | 把上一代命令流映射到本代寄存器的表驱动组件 |
| latch | 失败锁，重启前不自动解除 |
| 阶梯 | 只读 → TTL 替身 → 单 hook → 全 hook → 激活 的推进顺序 |
